# Неделя 8 — Оптимизация локальной модели под задачу

**Задание ментора:** оптимизировать локальную модель под конкретную задачу
(параметры: temperature / max tokens / context window; квантизация; свой prompt-шаблон);
сравнить качество до/после, скорость и потребление ресурсов.
**Результат:** ✅ Оптимизированная локальная LLM (`qwen-android`) под задачу
«Android/Kotlin interview prep RAG», с воспроизводимым бенчмарком `rag bench`.

Окружение: Apple M4 Pro / 24 GB · Ollama 0.31.1 · база `qwen2.5:7b` · облако
`google/gemini-2.5-flash` · индекс `android`.

---

## 1. Прикладная задача

**Ассистент подготовки к Android/Kotlin техническому интервью** поверх RAG.
Пользователь спрашивает про корутины, Compose, идиоматичный Kotlin — ассистент
отвечает **строго по контексту** из локального индекса, структурированно
(прямой ответ → ключевые пункты → возможный подвох), с цитатами.

## 2. База знаний (индекс из «другой» базы)

3 профильные книги (личные учебные материалы), сконвертированы из PDF → markdown и
проиндексированы **локально**:
- `kotlin-coroutines.md`, `compose-internals.md`, `effective-kotlin.md`
- индекс `android`: fixed-chunking, **675 чанков**, 768-dim, эмбеддинги
  `ollama/nomic-embed-text`. Retrieval полностью локальный.
- контрольные вопросы: `knowledge_base/eval/android_questions.json` (9 шт.).

## 3. Применённые оптимизации

Упакованы в артефакты-модели (`ollama create …`), плюс переключаемый in-app
prompt-шаблон:

| Рычаг | Базово | Оптимизировано | Где |
|---|---|---|---|
| **context window** (`num_ctx`) | 4096 | **8192** | Modelfile PARAMETER |
| **temperature** | по умолчанию | **0.2** (факты, стабильность) | Modelfile PARAMETER |
| **max tokens** (`num_predict`) | без лимита | **512** (короткие ответы, ниже латентность) | Modelfile PARAMETER |
| **prompt-шаблон** | общий | **android_interview** (коуч-персона, структура ответа) | `config set task_template` |
| **квантизация** | q4 (по умолчанию) | q8_0 — два профиля (см. ниже) | отдельные профили |

`num_ctx` вынесен в Modelfile намеренно: OpenAI-совместимый эндпоинт Ollama его
игнорирует, поэтому «увеличение окна» корректно делать на уровне модели. Проверка —
колонка `CONTEXT` в `ollama ps` (4096 → 8192).

**Два q8-профиля — чтобы честно изолировать квантизацию:**
- `local-q8` — «сырой» `qwen2.5:7b-instruct-q8_0` (окно 4096, без тюнинга) — смешивает
  квантизацию с отсутствием оптимизаций.
- `local-q8-opt` — `qwen-android-q8` (Modelfile-двойник `qwen-android`: тот же num_ctx
  8192 / temperature / prompt, только q8). Сравнение `local-opt` (q4) ↔ `local-q8-opt`
  (q8) отличается **только разрядностью весов** — это чистый эффект квантизации.

6 профилей: `local-base` (до) → `local-opt` (после) → `local-q8` (сырой q8) →

## 5. Оценка: до / после / ресурсы (честный вывод)

Главное наблюдение: **оптимизация дала скорость и ёмкость контекста, но НЕ качество
грундинга.** Ранние маленькие прогоны (4×2) показывали скачок грундинга 62%→100%, но
это был **шум малой выборки** — на полном прогоне (27 сэмплов) он исчезает.

**Качество (до → после).** «Ответ подтверждён источниками» (мета-судья): `local-base`
70% → `local-opt` **70%** — без изменений. Лексическое покрытие даже чуть упало
(81% → 77%): оптимизированный prompt даёт более короткие ответы (меньше «сырых»
ключевых слов). Цитирование нужного источника — 100% везде (заслуга retrieval).
Вывод: **промпт/температура/длина не поднимают верность источникам** — на 7B это
ограничение возможностей модели, а не формулировки.

**Скорость (до → после).** Реальный выигрыш: latency mean **10565 → 6878 мс (−35%)**,
median **8825 → 5285 мс (−40%)**. `num_predict 512` обрезает длину, prompt заставляет
отвечать сжато. Облако быстрее локали (~2.6–3.4 с).

**Ресурсы.** Окно контекста 4096 → **8192** при **+8% VRAM** (4521 → 4882 MB) — дёшево.
Пропускная способность q4 ~46–47 tok/s.

**Квантизация (чистое сравнение q4 ↔ q8).** `local-opt` (q4) vs `local-q8-opt` (q8),
одинаковый тюнинг: грундинг 70% → 74% (**+4 п.п., в пределах шума** при flips 67%/33%),
ценой **VRAM +61%** (4882 → 7879 MB) и **пропускной −33%** (46 → 31 tok/s), плюс медленнее.
Вывод: **для этой задачи q8 не окупается** — много памяти и скорости ради качества на
уровне шума. (Сырой `local-q8` без тюнинга даже хуже: грундинг 63%, окно 4096.)

**Облако vs локаль (качество и стабильность).** Здесь разрыв реальный и устойчивый:
облако — грундинг **96%** против ~70% и **флипы вердикта 11%** против **67%** у локали.
То есть локальные ответы **нестабильны по верности**: 6 из 9 вопросов судья оценивает
то «подтверждено», то «нет» между повторами. Облако отвечает стабильно.

## 6. Вывод

Оптимизация под задачу **окупилась по скорости и ёмкости**, но **не по качеству**:
`qwen-android` отвечает на **~40% быстрее** с **вдвое большим окном контекста** при +8%
VRAM — однако верность источникам осталась на уровне базовой модели (грундинг ~70%,
ограничен возможностями 7B). **Квантизация q8 не окупается** (при том же тюнинге +61%
VRAM и −33% скорости ради качества в пределах шума). **Облако заметно лучше** по
верности (96%) и стабильности (флипы 11% против 67%).

Это честный и защищаемый результат: он показывает, **какой рычаг на что влияет** —
num_ctx / num_predict / temperature двигают скорость/длину/ёмкость, а не грундинг; для
роста именно качества нужны другие рычаги (retrieval-реранк, строгий IDK-гейт, больший
`k`, либо более крупная модель — 14B+).

> Цифры — полный прогон 9×3 (27 сэмплов/профиль). Меньшие прогоны (4×2) сильно шумят —
> особенно строки «judge-verdict flips».

## 7. Как воспроизвести (CLI)

```bash
ollama create qwen-android    -f models/qwen-android.Modelfile       # оптимизированная модель (q4)
ollama pull  qwen2.5:7b-instruct-q8_0                                # сырой q8
ollama create qwen-android-q8 -f models/qwen-android-q8.Modelfile    # тюнингованный q8 (чистое сравнение)
python -m jarvis
> rag bench name=android repeats=3
```
Полностью локальный режим ассистента:
```
> config set provider ollama
> config set model qwen-android
> config set task_template android_interview
> config set rag on
> config set rag_index android
> rag ask what is structured concurrency
```
